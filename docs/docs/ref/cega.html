      Tactic

      cega

      Proves numerical bounds: inequalities on a box of real variables, closed constants and interval integrals.

      cega
      proves a numerical bound: an inequality on real variables that the hypotheses bound by rationals, a bound on a closed constant, or a bound on an interval integral.
      cega (prec := n) (depth := n) (panels := n)
      the same with the precision, the depth of subdivision and the number of integration panels set by hand.
      cega [fast]
      tries finite certificates first, checked by compiled code when cega.nativeCertificates is on, and is bare cega otherwise.
      cega [use_floats]
      rounds enclosure endpoints outward into binary64. cega [use_floats] (arith := F) chooses the IEEE format F, and cega [use_floats := false] selects exact rational endpoints.
      cega [batch := n]
      proves a goal ∀ i : Fin m, p i by checking n indices at a time in the kernel.
      cega [fast, batch := n]
      the same, with the batches checked by compiled code when cega.nativeCertificates is on.

      cega is the tactic I use for numbers. A bound like sinx≤0.85 for x∈[0,1] is true, obvious from a plot and tedious to prove by hand. cega encloses the expression on the box that your hypotheses describe, compares the enclosure with the bound by exact rational arithmetic, and hands the kernel a certificate for the whole argument.

      The name is short for certified enclosures, guarantees and approximations.

      Details and Options

      • The goal is a bound: f≤c, f<c, c≤f, |f|≤c, a two-sided bound, f ∈ Set.Icc a b (also Ioo, Ico, Ioc), f≤g, or a conjunction of these.
      • Every real variable needs rational bounds among the hypotheses: a ≤ x and x ≤ b, x ∈ Set.Icc a b, or |x| ≤ r. A goal without variables needs none.
      • When the first enclosure is too weak, the box is cut in halves, by default to depth 2. (depth := n) sets that depth.
      • A bound on one interval integral with rational limits, such as ∫abf≤c or |∫abf−c|≤ε, uses Simpson panels when the first four derivatives of f are certified on [a,b], and range panels, which need only continuity, otherwise. The number of panels doubles up to cega.maxIntegrationPanels, by default 256, and (panels := n) fixes it.
      • A real inequality that the box route does not prove goes to FloatLib’s interval, which reads the bounds in the hypotheses itself and is not limited by cega.maxDimension. It also proves bounds on finite sums, and it bounds a trigonometric polynomial in one variable by its coefficients, with no bounds on the variable. With floats on, it is not run, since it computes with exact rationals.
      • A closed goal that these routes refuse is tried with the tactic dyadic_interval at 32 bits, or at the bits of (prec := n).
      • The certificate propositions EnclosedOn, BoundOn and ApproxOn of SymLean are goals too.
      • The functions are those of N, written as Mathlib terms such as Real.sin x and Real.sqrt x. The box route takes at most 8 variables (cega.maxDimension).
      • set_option cega.nativeCertificates true lets the fast forms check finite certificates with compiled code. That also trusts Lean’s compiler, so it is off by default and every check stays in the kernel.
      • [use_floats] rounds each lower endpoint toward −∞ and each upper endpoint toward +∞ into binary64, and the kernel evaluates every operation. (arith := F) selects another IEEE binary format of FloatLib, such as binary32, binary128, FloatFormat.ieee 15 112 or "binary(p := 113, emax := 16383)", and turns floats on by itself. The flag shares its bracket group with fast, as in cega [fast, use_floats].
      • set_option cega.arithmetic "binary64" sets the default arithmetic. A call can override it: cega [use_floats := false] and the explicit query with (arith := "exact") both use exact endpoints. Certificates shows how to set the default in Lake.
      • When the goal states its bound with numerals, bare cega first tries FloatLib’s check, a refutation of the negation of the bound that bisects the box where it needs to, within cega.maxRefinementWork evaluations, and then the box query. With floats on, the query is the plain interval evaluation, on a uniform subdivision of depth (depth := n). In a float format neither has the monotonicity argument of the exact planner, so a sharp bound needs some room or a larger depth. A bound on an integral is computed with exact rationals and is not run. A float call that does not prove its goal fails with the format and the reason, and never computes with rationals in its place.
      • cega [batch := n] and cega [fast, batch := n] need import CAS.Numerics.Tactic.
      • A false bound, or a true one that the enclosures do not reach, is refused, and the message proposes the next call to try.
